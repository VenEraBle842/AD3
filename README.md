Бинарное дерево поиска и множество на его основе. Пункты ТЗ: вставка, поиск, удаление, `map`, `reduce`, `where`, строковое представление, извлечение поддерева, операции над множествами, проверка включения и равенства, перегрузка операторов.

## Возможности

- `BinarySearchTree<T, Compare>`: вставка уникальных ключей, поиск, удаление, извлечение независимой копии поддерева, копирование и перемещение.
- Шесть обходов в глубину и поуровневый обход, ASCII-печать структуры дерева.
- `Set<T, Compare>`: объединение, пересечение, разность, проверка включения и равенства множеств.
- `map`, `where` и `reduce` для дерева и множества.
- Сериализация и восстановление дерева и множества из строки.
- Работа в консольном меню с `int`, `double`, `std::string` и моделью `Student`.

Дерево не балансируется. Поиск, вставка и удаление занимают $O(h)$, где $h$ — высота дерева: в среднем для случайных ключей $O(log N)$, в худшем случае $O(N)$. Последовательная вставка отсортированных ключей может занять $O(N^2)$. Обходы, копирование и сериализация выполняются итеративно с собственными стеком и очередью.

В демонстрации множеств `A` заполняется из текущего дерева, а `B` — двумя введенными элементами и, если дерево непустое, его минимальным элементом.

Генератор тестовых данных имеет особенности:

- Для `int` и `double` заполняет дерево до указанного общего размера, а не добавляет указанное число новых элементов.
- Для `double` использует значения с одним знаком после запятой в диапазоне `[1.0, 100.0]`. Максимальный целевой размер при автоматическом заполнении — 991 элемент; превышение ограничения вызывает сообщение об ошибке.
- Для строк использует фиксированный список из 10 слов, для студентов — 7 записей. Повторные вызовы не создают дубликаты.

## Использование в коде

### Дерево поиска

```cpp
#include "tree/binary_search_tree.hpp"
#include <iostream>

int main() {
    BinarySearchTree<int> tree;
    for (int value : {4, 2, 6, 1, 3}) {
        tree.insert(value);
    }

    std::cout << tree << '\n';                  // [1, 2, 3, 4, 6]
    std::cout << tree.search(3) << '\n';        // 3
    std::cout << tree.insert(3) << '\n';        // 0: ключ уже есть

    auto subtree = tree.getSubtree(2);          // Копия поддерева: 2, 1, 3
    auto even = tree.where([](int x) { return x % 2 == 0; });
    auto doubled = tree.map([](int x) { return x * 2; });
    int sum = tree.reduce([](int acc, int x) { return acc + x; }, 0);
    std::cout << sum << '\n';                   // 16

    auto restored = BinarySearchTree<int>::deserialize(tree.serialize());
    tree.remove(4);
    restored.printAscii();
}
```

`insert` возвращает `false` для существующего ключа, `remove` — для отсутствующего. `contains` проверяет наличие без исключения. `search` возвращает `const T&`, а при отсутствии ключа выбрасывает `NodeNotFoundException`; то же исключение используется в `getSubtree`, если корень не найден.

`map` и `where` создают новые структуры. Если преобразование `map` дает одинаковые ключи, они объединяются в один элемент. `reduce` обрабатывает значения в порядке `LKP`, передавая функции аккумулятор и текущий элемент.

Уникальность определяется компаратором: ключи эквивалентны, если ни один не меньше другого. По умолчанию используется `std::less<T>`. Пользовательский тип должен поддерживать необходимые операции сравнения, а для текстового представления — потоковые `<<` и `>>`.

### Порядки обхода

`traverse(order)` возвращает `DynamicArray<T>`, а `forEach(order, action)` вызывает функцию для каждого значения.

В названиях `K` означает корень, `L` — левое поддерево, `P` — правое.

| `TraversalOrder` | Порядок |
| --- | --- |
| `KLP` | Корень &rarr; левое &rarr; правое (pre-order) |
| `KPL` | Корень &rarr; правое &rarr; левое |
| `LKP` | Левое &rarr; корень &rarr; правое (in-order) |
| `PKL` | Правое &rarr; корень &rarr; левое |
| `LPK` | Левое &rarr; правое &rarr; корень (post-order) |
| `PLK` | Правое &rarr; левое &rarr; корень |
| `BFS` | По уровням, слева направо |

При стандартном компараторе `LKP` выдает значения по возрастанию, `PKL` — по убыванию. Оператор `<<` дерева выводит значения в порядке `LKP`. Равенство деревьев сравнивает значения в этом порядке, а не форму деревьев.

### Множества

```cpp
#include "set/set.hpp"
#include <iostream>

int main() {
    Set<int> a{1, 2, 3, 4};
    Set<int> b{3, 4, 5};

    std::cout << (a + b) << '\n';               // {1, 2, 3, 4, 5}
    std::cout << (a * b) << '\n';               // {3, 4}
    std::cout << (a - b) << '\n';               // {1, 2}
    std::cout << (Set<int>{3, 4} <= a) << '\n';  // 1

    auto restored = Set<int>::deserialize(a.serialize());
    std::cout << (restored == a) << '\n';       // 1
}
```

Именованные аналоги операторов: `unionWith`, `intersectWith`, `differenceWith`, `isSubsetOf`. Также доступны `insert`, `remove`, `contains`, `size`, `empty`, `clear`, `map`, `where`, `reduce` и доступ к внутреннему дереву только для чтения через `getInternalTree()`.

### Модель Student

`Student` содержит `id` (`uint64_t`), `firstName`, `lastName`, `birthYear` и `gpa`. Упорядочивание и уникальность в дереве и множестве определяются только `id`, а `Student::operator==` сравнивает все поля. Поэтому для поиска достаточно объекта с нужным ID:

```cpp
#include "models/student.hpp"
#include "tree/binary_search_tree.hpp"

BinarySearchTree<Student> students;
students.insert(Student(101, "Ivan", "Ivanov", 2003, 4.8));
const Student& found = students.search(Student(101, "", "", 0, 0.0));
```

Повторная вставка записи с тем же ID не обновляет существующую запись.

## Форматы сериализации

| Объект | Формат | Пример |
| --- | --- | --- |
| Дерево | Pre-order с `#` для отсутствующих потомков | `2 1 # # 3 # # ` |
| Пустое дерево | Один маркер | `#` |
| Множество | Значения в порядке `LKP` между отдельными токенами `{` и `}` | `{ 1 2 3 }` |
| Студент | Поля через двоеточие | `101:Ivan:Ivanov:2003:4.8` |

Сериализация дерева сохраняет его форму. Сериализация множества сохраняет элементы, но не форму внутреннего дерева. Вывод множества через `<<` содержит запятые (`{1, 2, 3}`) и отличается от формата `serialize()`.

Форматы не предусматривают экранирование: значения строк не должны содержать пробелы и служебные токены, а имена и фамилии студентов — двоеточия. Числа с плавающей точкой выводятся со стандартной точностью потока, поэтому точное восстановление произвольного `double` не гарантируется.

Десериализация рассчитана прежде всего на строки, созданные `serialize()`. Проверка входа неполная: в частности, восстановление дерева не проверяет свойство BST, полноту структуры и отсутствие лишних токенов. Некоторые ошибки разбора приводят к `ParseException`, а ошибки преобразования числовых полей студента могут дать стандартные исключения.

## Бенчмарк и график

Запускайте из корня проекта, чтобы CSV и график создавались в ожидаемом месте:

```bash
./build/benchmark_runner
```

Программа использует `std::mt19937_64` с seed `1337` и измеряет операции для 10 000, 25 000, 50 000, 75 000, 100 000, 250 000, 500 000, 750 000 и 1 000 000 уникальных ключей типа `uint64_t`:

1. Заполнение дерева до `N` элементов случайными ключами из диапазона `[1, 10N]`.
2. 10 000 поисковых запросов: половина к заведомо существующим ключам, половина к случайным.
3. Удаление `N/2` ранее вставленных элементов.

Результаты записываются в `benchmark_results.csv` с колонками `Size,InsertTimeMs,SearchTimeMs,RemoveTimeMs`. Время указано в миллисекундах за весь этап. Замер вставки также включает генерацию ключей и сохранение успешно вставленных ключей во вспомогательный массив.

Для построения графика создайте Python-окружение и установите зависимость:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install matplotlib
python benchmark/plot_results.py
```

Скрипт сохраняет `benchmark_plot.png` и открывает окно графика. Для запуска без графического интерфейса:

```bash
MPLBACKEND=Agg python benchmark/plot_results.py
```

Замеры служат учебной иллюстрацией: выполняется один прогон на размер без усреднения. Результат `contains` в поисковом цикле не используется, поэтому оптимизирующий компилятор может повлиять на достоверность этого замера. Подписи сложности на графике описывают ожидаемое поведение при случайных ключах; балансировка дереву не гарантируется.

Каталоги сборки, `.venv`, CSV и PNG бенчмарка исключены из Git через `.gitignore`.
